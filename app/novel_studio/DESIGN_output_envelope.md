# Novel Studio 输出信封（Output Envelope）设计

> 目标：把叙事管线里「面板/系统状态/世界时间」等元素从自由文本升级为**通用结构化数据**，
> 同时保持**正文叙事不受破坏**。核心原则：**正文自由文本流 + 独立结构化块**，
> 且 schema 与 pipeline 消费逻辑**零故事概念**（不懂"抽卡/天赋/根骨"任何一词）。

---

## 1. 设计原则

1. **正文 = 自由文本流**。对话、旁白、心理、动作在正文中自然交织，**不拆类型**。
   强制切成 `dialogue:/narration:/action:` 会剧本化、破坏叙事流畅度（质量三要素之一）。
2. **结构化 = 只用于"与正文分离"的东西**：可展示面板、世界时间、场景引用等元数据。
3. **通用性**：schema 与 pipeline 存取逻辑不含任何故事概念；具体面板长什么样、
   有哪些字段，完全由数据层（`custom_prompt` / 角色 `profile`）驱动 LLM 生成。
   **换小说，pipeline 代码一行不改。**

## 2. 三个输出通道（Output Envelope）

每次 LLM 输出 = 一个信封，三个通道各司其职：

```
┌─────────────────────────────────────────────┐
│ narrative  正文（自由文本，对话/旁白/心理/动作交织）│
│ panels     结构化面板（系统/游戏/状态面板）       │
│ meta       结构化元数据（世界时间/场景/在场角色）   │
└─────────────────────────────────────────────┘
```

### 2.1 `narrative` — 正文（自由文本）

包含对话、旁白、心理活动、动作。**不切类型**，保持连续叙事流。

### 2.2 `panels` — 结构化面板

通用面板 schema（任何"面板"——系统面板、游戏面板、状态面板、角色属性——都适用）：

```json
{
  "panels": [
    {
      "id": "system",
      "title": "万界抽卡系统",
      "sections": [
        {
          "id": "overview",
          "title": "当前状态",
          "fields": [
            {"key": "绑定宿主", "value": "陈默"},
            {"key": "下次抽取", "value": "23:59:57"}
          ]
        },
        {
          "id": "records",
          "title": "抽卡记录",
          "list": [
            {"seq": 1, "talent": "根骨鉴定", "desc": "可查看目标资质"}
          ]
        }
      ]
    }
  ]
}
```

**约束：**
- `sections[].fields` 是键值条目数组（`{key, value}`）
- `sections[].list` 是记录列表（`[ {字段:值, ...} ]`），用于同类多行记录
- `fields` 与 `list` 二选一或并存
- 值类型：`string | number`，字段名/值由 LLM 按数据层设定生成

**同样的 schema 用于完全不同的书（证明通用、非定制）：**

```json
{ "panels": [ {
  "id": "status", "title": "陈实 · 状态",
  "sections": [ {
    "id": "basic", "title": "身份",
    "fields": [
      {"key": "身份", "value": "崇祯四年·流落冀北"},
      {"key": "粮", "value": "3斤炒面"},
      {"key": "伤", "value": "左臂箭伤"}
    ]
  } ]
} ] }
```

### 2.3 `meta` — 结构化元数据

```json
{
  "world_time": "崇祯四年·秋",
  "scene_id": "scene_3",
  "location": "破庙",
  "present": ["陈实", "铁柱"]
}
```

- `world_time`：世界内时间（供时间线一致性检查）
- `scene_id`：引用场景规划层（空间连贯性检查），不重复定义场景
- `location` / `present`：辅助定位

## 3. 各层输出位置

| 层 | 输出位置 | 说明 |
|---|---|---|
| 角色决策（character_action） | action JSON 新增可选 `panels`（list[dict]） | 旧「面板」自由文本保留兼容 |
| 叙事合成（narrative） | 正文自由文本；action 的 panels 渲染为可读文本注入，并持久化到章节 | 正文仍展示面板 |
| 存储（Chapter 模型） | 新增 `panels: list[dict]` 字段 | 供前端渲染 / 跨章一致 |
| 前端 | 把结构化 panels 渲染为视觉面板（标签+值 / 表格） | 后续阶段 |

## 4. 定制边界（红线保障）

| 层 | 内容 | 是否定制 |
|---|---|---|
| schema / pipeline 存取 / 渲染逻辑 | 通用「面板=标题+分组+字段/列表」 | ❌ 通用 |
| 该角色有哪些面板、面板标题、字段 | 角色 profile / custom_prompt 驱动 LLM | ✅ 数据层 |
| 具体故事概念（抽卡/天赋/根骨/崇祯） | 只存在于数据与提示词 | ✅ 数据层 |

pipeline 代码只做：接收 panels 结构化块 → 持久化 → 供渲染。**换小说，pipeline 一行不改。**

## 5. 落地路径（分阶段）

1. **本次**：设计文档 + 决策解析层支持结构化 `panels`（`_parse_decision` 扩展，保留兼容）+ Chapter 模型新增 `panels` 字段 + 单测锁定解析。
2. **后续**：narrative 消费结构化 panels（渲染注入正文 + 持久化）。
3. **后续**：前端把结构化 panels 渲染为视觉面板。

> 面板/元数据是否输出、长什么样，完全由数据层驱动——管线只提供"能解析、能存、能渲染"的通用能力。
